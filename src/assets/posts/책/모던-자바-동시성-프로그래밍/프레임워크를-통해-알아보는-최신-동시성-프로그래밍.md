:::callout 🎯** 챕터 목표**
:::callout 주요 프레임워크들이 가상 스레드를 어떻게 수용하고 있는지 살펴본다.
:::callout 스프링 부트, 쿼커스, 자카르타 EE를 다루며 실질적인 설정 예제와 모범 사례를 제공한다.

`JDK 21`에서 가상 스레드가 도입되면서 자바 생태계를 구성하는 여러 프레임워크가 동시성을 처리하는 방식에 중요한 변화가 나타났다.
- 현대적인 프레임워크가 성능, 확장성, 자원 효율성을 개선하기 위해 가상 스레드를 적극적으로 수용한다.
## 스프링 부트
 전통적인 스프링 부트 웹 애플리케이션은 <span class="text-red">**요청당 스레드(Thread-Per-Request)**</span> 모델을 주로 사용해왔다.
- **각 클라이언트 요청마다 전용 플랫폼 스레드 하나가 할당**
- 동시에 I/O 집중적 요청이 많이 들어올 경우 확장성 문제가 발생

이를 완화하기 위해 `@Async`, `TaskExecutor` 같은 추상화를 통해 비동기 프로그래밍 기능을 도입
- 하지만 이도 제한된 개수의 플랫폼 스레드 풀에 의존한다.
- 유하한 스레드 풀에서 각 요청이나 태스크가 하나의 스레드를 소비하여 높은 부하 상황에서는 성능 병목으로 이어질 수 있다.
```java
@Configuration
public class ThreadPoolConfig {
	@Bean
	public AsyncTaskExecutor applicationTaskExecutor() {
		ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
		executor.setCorePoolSize(10);
		executor.setMaxPoolSize(100);
		executor.initialize();
		return executor;
	}
}
```


<span class="text-blue">**스프링 부트 3.2**</span>(스프링 프레임워크 6.1 기반) 가 출시되며 가상 스레드를 공식적으로 확장한 자바 21을 지원하게 되었다.
- 가상 스레드 설정을 활성화하게 되면 애플리케이션 전반에서 가상 스레드가 사용된다.
스프링 부트는 별도의 커스텀 이그제큐터 빈이 정의되지 않은 경우 자동 구성을 통해 가상 스레드를 기반으로 하는 `AsyncTaskExecutor` 빈을 등록한다. 이때 내부적으로 `SimpleAsyncTaskExecutor` 를 사용해 다음과 같은 여러 동시성 관련 기능에 자연스럽게 적용된다.
- 비동기 태스크 실행
- 스프링에서 Callable 반환값을 사용하는 비동기 처리
- 스프링 웹 MVC의 비동기 요청 처리
- 스프링 웹플럭스에서의 제한적인 블로킹 실행 지원
### 예시
```java
@RestController
public class GreetingsController {
    private static final Logger LOGGER
            = LoggerFactory.getLogger(GreetingsController.class.getName());

    @GetMapping("/hello")
    public String hello() {
        LOGGER.info("Received request for /hello");
        LOGGER.info("Running on {}", Thread.currentThread());

        return "Hello from Spring Boot";
    }
}
```

가상 스레드가 활성화된 스프링부트 애플리케이션을 실행 후 `curl` 요청을 전송하면 아래 로그가 출력된다.
```plain text
.... GreetingsController - Received request for /hello
.... GreetingsController - Running on VirtualThread[#63, tomcat-handler-0]/runnable@ForkJoinPool-1-worker-1
```


#### **스케줄링된 태스크**
```java
@EnableScheduling
@Component
public class ScheduledTasks {
    private static final Logger LOGGER
            = LoggerFactory.getLogger(ScheduledTasks.class.getName());

    @Scheduled(fixedRate = 1000)
    public void scheduledTask() {
        LOGGER.info("Scheduled task running on:  {}", Thread.currentThread());
    }
}
```


**로그 출력**
```plain text
... ScheduledTasks - Scheduled task running on: VirtualThread[#105, scheduling-36]/runnable@ForkJoinPool-1-worker-5
```

### 수동 구성
스프링 부트 3.2 이전 구 버전을 사용하거나 이그제큐터 설정을 더 제어하기를 원한다면 명시적으로 이그제큐터를 정의할 수 있다.

#### ex) 이그제큐터가 가상 스레드를 사용하도록 applicationTaskExecutor 빈을 명시적으로 정의하는 방법
```java
@Configuration
public class VirtualThreadConfig {

    @Bean
    public AsyncTaskExecutor applicationTaskExecutor() {
        return new TaskExecutorAdapter(Executors.newVirtualThreadPerTaskExecutor());
    }
}
```

스프링 비동기 프로그래밍 모델에서 `@Async`를 붙인 메서드는 `applicationTaskExecutor` 빈에 의존한다. 플랫폼 스레드를 사용하는 기본 이그제큐터 대신 **가상 스레드 기반의 이그제큐터를 사용하면 @Async를 붙인 메서드는 가벼운 가상 스레드를 사용하게 된다.**

#### ex) 아파치 톰캣의 확장성, 자원활용
내장 웹 서버의 확장성과 자원 활용도 가상 스레드를 활용하여 개선할 수 있다.
- 아파치 톰캣의 경우 TomcatProtocolHandlerCustomizer 빈을 정의하여 프로토콜 핸들러가 가상 스레드를 사용하도록 설정할 수 있다.
```java
@Configuration
public class TomcatConfig {

  @Bean
  public TomcatProtocolHandlerCustomizer<?> virtualThreadExecutor() {
    return protocolHandler
        -> protocolHandler.setExecutor(
              Executors.newVirtualThreadPerTaskExecutor());
  }
}
```


:::callout 💡 **프로토콜 핸들러(Protocol Handler)**
:::callout 톰캣의 커넥터(Connector) 내부에서 작동하며 외부 클라이언트가 보낸 네트워크 요청의 프로토콜을 이해하고 소켓 I/O 및 스레드를 관리해 서블릿 컨테이너로 전달하는 핵심 컴포넌트
## 쿼커스 (Quarkus)
:::callout 💡 **쿼커스**
:::callout 개발자 생산성, 빠른 기동 시간, 효율적인 성능을 강조하도록 설계된 현대적인 자바 프레임워크
:::callout - 마이크로서비스와 서버리스 애플리케이션을 구축하는데 적합
`Vertx(버트엑스)`를 바탕으로 한 리액티브 프로그래밍 패러다임을 적용한 쿼커스는 동시성 애플리케이션에 더 적합하도록 의도적이고 명시적으로 **가상 스레드를 지원**한다.

쿼커스는 가상 스레드를 전역적으로 적용하는 방식 대신 <span class="text-brown">**특정 애너테이션**</span>**을 통해 필요한 곳에만 가상 스레드를 도입하는 방식을 적용했다.**
`@RunOnVirtualThread` 애너테이션을 메서드에 적용해 특정 엔드포인트나 서비스에서 선택적으로 가상 스레드를 활성화 할 수 있다.
- 이 애너테이션은 해당 메서드를 플랫폼 스레드가 아닌 가상 스레드에서 실행하도록 쿼커스에게 지시
## 자카르타 EE
**자카르타 동시성**은 **자카르타 EE **런타임의 혜택을 누리면서 동시성을 활용할 수 있게 해주는 표준 명세이다.
`자카르타 동시성 3.1`에서는 가상 스레드 지원이 도입되어 자바 21의 경량 스레딩 모델을 활용할 수 있게 된다.
다음 애너테이션에 `virtual = true`를 지정함으로 가상 스레드를 활성화할 수 있다.
- `@ManagedExecutorDefinition`
- `@ManagedScheduledExecutorDefinition`
- `@ManagedThreadFactory`
